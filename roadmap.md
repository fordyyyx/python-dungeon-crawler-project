# Dungeon Crawler — Development Roadmap

Ordered by dependency, not necessarily by desire — each item is placed after
whatever it structurally relies on. Update this file as items are completed,
reordered, or new ideas come up.

## Completed
- [x] Bug fixes (Chiron's hint reverting after trade, deflected damage not shown, unlocked skills not in `stats`, Wounded Soldier's hint not naming his items)
- [x] Combat loop consolidated into `resolve_attack_and_check_defeat()`
- [x] Toggleable auto-talk setting
- [x] Enemy memory after fleeing — `Enemy.has_been_fled_from` flag, set in `flee_combat()`, checked in `print_room()` to vary the room-entry message on a repeat encounter. *(Note: still needs including in the save/load delta-tracking model once that's built.)*
- [x] `controls` command — always shows the full command list, checked ahead of the combat-lock branch (same as dev commands) so it's available regardless of state. Duplicates the README's Controls section by design (no shared source) — see `CLAUDE.md` for the reminder to keep both in sync.
- [x] Dev tooling — full command set built and working: generic `dev set <stat> <value>` (reads/writes any named `Player` attribute, so new stats like Intellect, mana, or max_mana work automatically with zero extra code), `dev add`, `dev spawn`, `dev remove`/`dev remove all`/`dev clear room` (three distinct removal scopes, none trigger loot), `dev kill` (reuses `handle_enemy_defeat()`), `dev teleport` (case-insensitive room lookup), `dev learn`, `dev unlock`/`dev unlock all`, floor-start selection via "developer mode" as a name, plus a dedicated blank Dev Test Room (registered in the `Map` via `build_dev_test_room()`, not added to any floor's room dict, reachable purely via `dev teleport dev test room`). Combat-lock bypass bug fixed — dev commands are now checked ahead of the `in_combat` branch in `main()`'s routing. *(Two bugs found and fixed during playtesting: (1) using an item mid-combat showed the enemy's counter-attack but no HP status line — consolidated into a shared `format_hp_line()` helper. (2) `dev spawn` was printing the raw `(message, None)` tuple instead of the message alone.)*
- [x] Expanded exploration commands — `examine` (alone) shows a room's `examine_text` and reveals any `Room.hidden_exits`; `examine <item>` reuses the existing `Item.description` rather than a new field.
- [x] XP and gold on kill / levelling system — `Enemy` gained `experience_reward`/`gold_reward`, `Player` gained `gold`, `gain_experience()`, and `level_up()` (grants a skill point, rolls the XP threshold forward by ×1.5). `handle_enemy_defeat()` now takes `player` as a parameter and grants both rewards.
- [x] Intellect stat — lives on `Player` only, set by ancestry, grown by 1 automatically on every `level_up()`. `Room` gained `examine_text`/`required_intellect`. ***Revised since*** — the original rule ("Intellect never gates required progress") was tightened: Intellect *can* gate progress, including the hidden-exit reveal itself, since it grows every level with no cap and nothing is ever permanently unreachable.
- [x] Docstrings and comments retrofit — every function/class/method now has a docstring.
- [x] Enemy `choose_action()` + multiple enemies per room — built as team-vs-team from the start: combat resolution works over `player_team`/`enemy_team` plain lists (no `Team` class), player acting first each round followed by every still-living enemy via the standalone `choose_enemy_action()`. Utility-based scoring (`_score_candidate_actions()` plus random noise) across three actions: Attack, Defend/Brace, Heal. New player-facing `target <name>`/`target <name> <number>` command, with stable disambiguation numbering; `format_hp_line` generalized to a full N-combatant display. **Known follow-up, fix decided and now built** (see `CLAUDE.md`): Defend's score redefined around genuine incoming danger rather than raw missing-HP%.
- [x] **Companions** — `Companion(Character)` (real combat stats, unlike the stat-less `Ally`), holding `home_room`, `required_items`, and the same `aggression_weight`/`caution_weight`/`randomness_weight`/`brace_amount`/`heal_amount` fields as `Enemy`. `Player.companion` is a plain attribute; a new `Player.team` property returns `[player]` or `[player, companion]` (automatically excluding a downed companion, `hp == 0`). `recruit_companion()`/`dismiss_companion()` (`exploration.py`) mirror `trade_with_ally()`'s exact item-consumption mechanics, routed via `recruit <name>`/`dismiss`. `choose_companion_action()`/`choose_companion_target()` (`combat.py`) mirror `choose_enemy_action()`/`choose_enemy_target()` — separate functions per `CLAUDE.md`'s decision, though the underlying per-candidate scoring is fully shared. A downed companion isn't dead — `on_death()` returns a distinct "downed, recoverable" message; `Reviver(Consumable)` restores them, and dismissing a downed companion also restores them to full HP as a free alternative to a Reviver. `engine.py`'s `attack` handler now passes `player.team`, not a hardcoded `[player]`, so enemies can genuinely target a companion. *(Known-gap update: `dev spawn` now has a companion lookup (`COMPANION_REGISTRY`, backed by `content.py`'s dev-only `create_test_companion()`), so `recruit` is reachable through `main()` via `dev spawn test companion` — see `dev_guide.md`. Still no room in `build_world()` places a recruitable `Companion` as real content, so this remains dev-tool-only until that's built.)*
- [x] **Dodge ability** — new Abilities-path skill (`DodgeSkill`), a flat, additive `Character.dodge_chance: float` (default `0.0`, same precedent as `has_thorns`/`brace_amount`) checked at the very top of `take_damage()` — a successful roll (`random.random() < self.dodge_chance`) short-circuits the entire method, returning `0, "<name> dodges the attack!"` before any Defend/Brace or armour math runs, so a dodge means the hit never landed at all rather than being reduced to zero. Fourth skill in the Abilities path, alongside Double Strike/Thorns/Last Stand — deliberately breaks the 3/3/4 symmetry with Attack/Defence, accepted as fine. Shipped as "Nimble Grace," 15% chance.
- [x] **Armour split — helmet and body** — `Armour` gained a `slot: str = "body"` field (`"body"` or `"helmet"`); `Character` gained two independent equip slots, `equipped_helmet` and `equipped_body`, replacing the old single `equipped_armour`. `Armour.use()`/`unequip()` read/write `getattr(character, f"equipped_{self.slot}")` — only same-slot items are ever swapped, so a helmet and a body piece can be worn simultaneously, each adding its own `defence` into the same `Character.armour` accumulator (mirrors how `Weapon` already works for `attack_damage`). *(Resolved as anticipated when this was planned: `Enemy` never needed to change — it still only has a flat `armour`/DEF number, no equip slots of its own. No content currently uses `slot="helmet"` — every existing `Armour` item defaults to `"body"` — worth revisiting once "Populate all floors" adds real helmet drops.)*
- [x] **Armour durability + repair at the Forge of Prometheus** — `Armour` gained `max_durability: int = 10` / `durability` (starts full). `Character.take_damage()` decrements durability by 1 on every equipped piece (helmet *and* body) on every hit taken — even one fully blocked by armour — and once a piece's durability reaches exactly 0, its `defence` bonus is backed out of `Character.armour`, though the piece stays equipped rather than auto-unequipping. **Subtlety worth remembering**: durability degrades *after* that hit's damage is already calculated, so the hit that actually breaks a piece still benefits from its defence — only the *next* hit loses the protection. `Room` gained `is_forge: bool = False` (only Forge of Prometheus, floor 2, is one). `repair_item(item_name, player, room)` (`exploration.py`), routed via `repair <item>`, only works at a forge, costs `REPAIR_COST_PER_POINT = 2` gold per point of missing durability, and restores full durability, re-adding the `defence` bonus if the piece had dropped to 0.
- [x] **Status-effect items (poison/flame/heal-over-time)** — new `status_effects.py`: `StatusEffect(name, amount, duration)` — `amount < 0` deals damage each tick, `amount >= 0` heals; `tick(character)` applies one tick and decrements `duration`. `Character` gained `active_effects: list[StatusEffect]`, `apply_status_effect()` (reapplying an effect with the same name **prolongs its duration**, per the decided stacking rule — reapplication never changes `amount`, only `duration`), and `tick_status_effects()` (ticks every active effect, removing any that expire, and stopping the moment a tick kills the character — same "stop once dead" precedent as the combat round loop — appending the death message when that happens). `StatusEffectItem(Consumable)` (`items.py`) applies to the user themselves when `amount >= 0`, or to `player.current_target` when `amount < 0` (reusing the existing `target` command as the way to aim an offensive one, rather than a new `use <item> on <target>` syntax, as decided). Wired into `resolve_combat_round()`/`handle_combat_command()` so every combatant — player, companion, each enemy — ticks its own effects at the start of its own turn, with a lethal tick correctly skipping that combatant's turn entirely (a real bug found and fixed, same category as the player-death guard).
- [x] **Spells (offensive/defensive)** — new `spells.py`: `Spell(name, description, mana_cost, damage=0, heal_amount=0, effect_name=None, effect_amount=0, effect_duration=0)` — damage, heal, and status-effect components are all optional and freely combinable within one spell. `Player` gained `known_spells: list[Spell]`, `mana`/`max_mana` (both default `20`), `spell_cooldowns: dict[str, int]`, `tick_spell_cooldowns()`. `SpellBook(Consumable)` (`items.py`) permanently teaches its spell (raises if already known). New `cast <spell>` command (`handle_combat_command()`) validates known/not-on-cooldown/enough-mana, deducts `mana_cost`, and sets a flat 1-turn cooldown (every spell currently shares the same cooldown length — no per-spell variation yet). **Resource model, as decided and built**: mana recovers via a new `rest`/`wait` command (`engine.py`, exploration-only, `REST_MANA_AMOUNT = 10` per use) rather than passive per-turn regen. **`would_fail()` guard pattern, built to preserve "a failed action costs nothing"**: `Spell.would_fail(caster, target)` and `Item.would_fail(character)` (default no-op, overridden by `StatusEffectItem`/`SpellBook`) let `combat.py` fully validate a `cast`/`use` *before* ticking anything. *(A real bug found and fixed here: ticking used to run **after** the action, so a freshly-cast spell's own new cooldown/effect could be immediately consumed by that same tick before it ever really took hold — cooldowns silently never blocked a repeat cast, and a self-cast heal-over-time got its first tick "for free" the instant it landed. Fixed by validating fully, then ticking pre-existing state, then committing the new action — so only state that existed *before* this turn is ever touched by "this turn's" tick.)* Spells are player-only for now — `Enemy`/`Companion` AI has no casting candidate action; that stays a possible future extension of the existing utility-scoring system, not built yet.
- [x] **Attack variety (light/heavy/ranged) + refined turn economy** — `Character.attack(target, attack_type="light")` now branches on `attack_type`: `"light"`/`"ranged"` deal a guaranteed hit (weapon-inclusive, no multiplier), `"heavy"` multiplies the total by `HEAVY_ATTACK_MULTIPLIER` (`1.75`) but has a `HEAVY_ATTACK_MISS_CHANCE` (`0.3`) chance to miss entirely (0 damage, turn still spent) — **decided heavy attack trade-off: a chance to miss, not a separate stamina resource**, as originally planned. `Weapon` gained a `slot: str = "melee"` field (`"melee"` or `"ranged"`), mirroring `Armour`'s helmet/body split — `Character` gained `equipped_melee_weapon`/`equipped_ranged_weapon` (replacing the old single `equipped_weapon`), and weapon damage is now read directly off the equipped slot at attack time rather than accumulated into `attack_damage` permanently. `handle_combat_command()`'s `attack` branch now accepts `attack`/`attack light`/`attack heavy`/`attack ranged` (an unrecognised type, or `ranged` with no ranged weapon equipped, returns an error message rather than attacking). **Refined turn economy**: `Item.ends_turn(character)` (default `True`, overridden by `Consumable`/`StatusEffectItem`) — a genuine heal is now a free action that doesn't end the turn (or let the enemy/companion act), while an offensive use, a non-healing use, or a spell cast still does. *(A real bug found and fixed while building this: `Character.turn_started` was never actually being set to `True` anywhere, so `tick_start_of_turn_if_needed()`'s guard against double-ticking status effects/cooldowns when a free action precedes a turn-ending one in the same round was a no-op. Fixed by setting it inside `tick_start_of_turn_if_needed()` itself.)* Spell attack variety (the `"spell"` option originally scoped here) was already covered by the existing `cast <spell>` command, so nothing further was needed there. Enemies/companions still don't use heavy/ranged themselves — attack-type variety is player-only for now, see `CLAUDE.md`.
- [x] **Practice chamber, with an infinitely-respawning, customisable practice dummy** — real, in-game content: a new "Practice Chamber" room on floor 2, connected east/west to the Forge of Prometheus, added to `build_floor_2()` (floor 2 now has six rooms, not five). `Enemy` gained `respawns: bool = False`; the room's dummy (`create_practice_dummy()`, `content.py`) is the first (and so far only) enemy with it set. `Room` gained `is_practice_chamber: bool = False`. **Respawn mechanics**: `handle_enemy_defeat()` special-cases `enemy.respawns` — instead of removing the enemy and granting loot/XP/gold, it resets `hp` to `max_hp`, clears `active_effects` and `pending_damage_reduction`, and returns a "resets, ready for another round" message. `resolve_attack_and_check_defeat()` gained a `still_relevant_enemies` filter (excludes any `respawns` enemy) so a solo respawning dummy correctly ends combat once "defeated," rather than looping forever since `handle_enemy_defeat()` just made it alive again. **Free spellcasting inside the chamber**: `handle_combat_command()`'s `cast` branch skips the cooldown/mana checks *and* skips deducting mana/setting a cooldown whenever `room.is_practice_chamber` — casting is entirely free while inside, exactly as originally planned (item and weapon use were already free of any resource cost, so nothing needed to change there). **Customisable stats**: reuses the *plumbing*, not the command, of `dev set <stat> <value>` as originally scoped — `dev_tools.py`'s core reflection/`STAT_ALIASES` logic was pulled out into a shared `_apply_stat()` helper, and a new `handle_dummy_set(stat_name, value_str, dummy)` reuses it for a genuinely new, undocumented-as-dev player command, `dummy set <stat> <value>` (message prefix `[Practice]`, not `[DEV]`; no `skillpoints` special case, since `Enemy` has no `skill_tree`) — routed in `main()` by finding the current room's `respawns` enemy, not gated by `DEV_MODE` at all. Added to `get_controls_text()`/the README's Controls section like any other real command.
- [x] **Ancestry system, expanded — primary + secondary ancestor** — a new `choose_secondary_ancestry(primary_key)` (`character_creation.py`) prompts for a second figure, excluding `primary_key` from the printed options and rejecting it if typed anyway (reprompting with a dedicated message) - **same figure can't be picked as both**, exactly as planned. `create_player()` gained a required third parameter, `secondary_ancestry_key`; it applies that entry's `secondary_effect(player)` callable and sets `player.secondary_ancestry_label` to the ability's description (shown as a new "Secondary gift: ..." line in `get_stats()`) - unless the secondary key matches the primary, or is `"basic"` (the deliberate "skip entirely" option, since `"basic"["secondary_effect"]` is `None`). Every `ANCESTRIES` entry gained `secondary_effect`/`secondary_ability_label`. **No stat effect from the secondary pick, ability only, exactly as decided** - each of the ten non-`"basic"` entries grants one flag on `Character`, checked far from the skill tree's own four ability flags: `has_reckless_strength` (Ares - removes the heavy attack miss chance entirely, `attack()`), `has_measured_casting` (Athena - spells never go on cooldown, `handle_combat_command()`'s `cast` branch - mana is still required/deducted normally), `has_swift_feet` (Hermes - `flee_combat()` always disengages cleanly, no free-hit roll at all), `has_unyielding_tide` (Poseidon - `take_damage()` never backs out armour's `defence` when a piece's durability breaks, though durability still degrades), `has_berserking` (Achilles - `attack()` adds +2 damage at or below half HP), `has_silver_tongue` (Odysseus - `trade_with_ally()` never actually removes the required items, though the trade still completes and the reward is still granted), `can_ranged_without_weapon` (Atalanta - `handle_combat_command()`'s `attack ranged` works with no equipped ranged weapon), `has_petrifying_gaze` (Medusa - `attack()` has a 15% chance to also poison a target that survives the hit, skipped entirely if the hit kills it), `has_bull_rush` (Minotaur - `attack()` adds +3 damage against a target still at full HP), `has_iron_hide` (Cyclops - `take_damage()` reduces the final damage by 1, floored at 0). *(Four real bugs found and fixed while building this: (1) the `cast` branch's mana check got nested inside a condition that made it unreachable for every player, not just those with `has_measured_casting` - fixed by restoring independence between the cooldown check (guarded by the flag) and the mana check (always enforced outside the practice chamber). (2) `has_reckless_strength` was declared and grantable but never actually read anywhere - `attack()`'s heavy-miss roll was unconditional until the flag was added to its condition. (3) A typo (`has_silver_tonuge`) in Odysseus' `secondary_effect` meant Silver Tongue could never trigger - the correctly-spelled attribute it should have set was never touched. (4) `create_player()` stored the ancestry's *primary* label into `secondary_ancestry_label` instead of the ability description, so the stats screen's "Secondary gift" line just repeated the ancestry name instead of saying what the gift actually did.)* `dev set <flag_name> 1` (the existing generic `dev set` command, unmodified) happens to work for granting any of the ten flags directly for playtesting, since `setattr` doesn't care that the value arrives as an `int` rather than a `bool` - see `dev_guide.md`.

## In order

1. **Save/load system — decided shape: 3 profiles, 5 save slots each, with delete and overwrite for both individual saves and whole profiles.** One file per save slot, one folder per profile (`saves/profile_N/slot_N.json` + a reserved-but-unused `achievements.json` per profile, for when Achievements (#4) lands). **Key insight**: since `build_world()` rebuilds an identical map every game start, a save never serializes the world graph — only Player's full state (a direct snapshot, not a delta — stats, all 14 ability flags, skill tree unlock counts, gold/level/XP/mana, both ancestry labels, known spells + cooldowns, active effects, inventory with equipped/durability, companion, current room) plus **per-room deltas only for rooms that have actually changed** (surviving enemies' HP/fled-status + which are gone, current item list, unlocked exits, completed trades, placed trophies). Untouched rooms cost zero save data. Enemies are matched on reload by name + ordinal position, reusing the exact stable-numbering scheme `get_enemy_display_name()`/`target <name> <n>` already established. **New convention**: anything that must survive a save (item/enemy/ally/companion/spell) needs a registry entry (`ITEM_REGISTRY` etc., `dev_tools.py`) — this was already true for `dev spawn`/`dev add`, save/load just makes it load-bearing.
   - **Title screen rework** (replaces the current name-prompt-first flow): New Game / Load Game / Delete Save / Quit. New Game prompts profile then slot (showing each slot's occupancy/summary), confirms before overwriting an occupied slot, proceeds immediately into an empty one — then name entry (the "developer mode" name-trick is unaffected) and ancestry selection as today. Load Game prompts profile then slot (occupied only), rebuilds the world, then patches in the save's deltas. Delete Save prompts profile then slot-or-whole-profile, then confirms. **This breaks every existing `test_main_*_smoke_test`** (they all assume the very first input is the player's name) — expected and accepted, tests get updated alongside this.
   - **Session state**: `main()` tracks a single "active slot" (`profile_num`, `slot_num`), set by New Game, Load Game, or any confirmed `save <profile> <slot>`/`load <profile> <slot>`. Both autosave and bare `save` always target whichever slot is currently active — never a fixed or inferred one.
   - **Manual save**: `save` (bare) targets the active slot, no confirmation. `save <profile> <slot>` targets explicitly and re-points the active slot to match; occupied → confirm overwrite, empty → proceeds immediately.
   - **Manual load (mid-game)**: `load <profile> <slot>` always confirms first — *"Loading will discard any unsaved progress since your last save. Continue?"* — even when reloading the currently active slot. An empty target slot returns an error message without prompting. Confirmed load re-points the active slot to match.
   - **Autosave**: fires on any floor-crossing exit (`ascend` or `descend`), gated by a new `Player.visited_floors: set[str]` so it only fires the first time a given floor is reached — deliberately avoids repeated overwrite churn from a player ascending/descending the same boundary repeatedly (currently harmless, but flagged for the eventual graphical port's real asset/write costs). Always targets the active slot, no confirmation.
   - **Deliberately deferred, not built now**: mid-fight boss-phase state isn't modeled — Multi-stage boss fights (#2) lands after this, so no boss can be mid-transition at a checkpoint yet; revisit once that item exists. `achievements.json`'s path is reserved, not written to yet.
2. **Multi-stage boss fights — decided design: no dedicated `Boss` class.** A boss is still a plain `Enemy` — the only new thing needed is an optional `next_phase_factory` attribute (a callable, following the existing `create_*()` factory pattern) rather than a subclass. Handled in defeat-handling (`handle_enemy_defeat()`), not inside `on_death()` itself. **Decided: transitions are seamless** — combat stays locked, `current_target` automatically updates to the next phase. Placed directly before "Populate all floors," since named late-game bosses (Hades, Typhon) are the actual reason this needs deciding before that content gets written.
3. **Populate all floors — enemies, allies, items, and trades, into the shell built via `build_floor_2()` through `build_floor_9()`.** Still deliberately last among core systems, since this genuinely depends on every mechanic (combat, items, skills, armour slots/durability, status effects, spells) being finalized first. *(Note: a lifesteal weapon, dropped as loot later in the game, fits naturally as content during this phase — as does content's first real `slot="helmet"` item, its first real `slot="ranged"` weapon (no ranged weapon exists in game content yet, dev-test or otherwise — see `CLAUDE.md`/`dev_guide.md`), and its first `StatusEffectItem`/`Spell`/`SpellBook` instances. Dev-only versions of the latter three already exist (`create_test_healing_tonic`/`create_test_venom_vial`/`create_test_spell`/`create_test_spellbook` in `content.py`, reachable via `dev add`/`dev grant spell`), but none are placed in any real room yet — this phase is where a genuine, narrative version of each first appears. Floor 2 also still needs its already-written `Athena`/`Ares`/`Hermes`/`Prometheus` allies and their trades actually wired into `build_floor_2()` — see `map.md`.)*
4. **Achievements, tied to a profile** — genuinely depends on save/load (#1), specifically the profile layer. Placed after floors are finished, since that's when the full roster of things worth achieving actually exists.
5. **Carry weight / inventory cap** — gives real purpose to the existing `drop` command. Cheap to add: give `Item.__init__` a `weight: int = 1` default. **Quest items must be exempt from the cap.** Placed after the floors are finished. **Decided shape**: a fixed base capacity for everyone, only ever modified by a one-time ancestry bonus and/or a skill/ability, never by levelling. **Resolved: equipped gear still counts toward the cap.**
6. **Trophy room — decided shape: a physical room, not an ally-respect mechanic.** A new `Trophy(Item)` subclass, dropped only by named mini-boss/boss/mega-boss enemies via the existing `loot` mechanic. A dedicated Trophy Room with wall slots, one per trophy that exists in the game. A new `place <trophy>` command, valid only in that room (`Room.placed_trophies: set[str]`). Placing every trophy unlocks a chest. **Genuinely depends on both #3 (full boss roster) and #7 (the chest payoff) — placed after both for that reason.**
7. **Charon shop, gold currency, searchable chests** — gold itself already exists (see Completed — XP and gold on kill); this item is where it actually gets spent.
8. **Standalone `.exe` build via PyInstaller** — `pyinstaller --onefile` bundles the whole game into a single downloadable executable. **Decided: automate via the existing GitHub Actions workflow** — extend it to build the `.exe` and attach it to the GitHub Release automatically on a version tag push. Windows-only per platform it's run on; file size 10–30MB; antivirus false positives are a known, harmless PyInstaller quirk. Placed last among the "real" content/systems.
9. **Easter egg: UUDDLRLRBA input sequence** — grants a secret legendary item or activates God Mode. Genuinely trivial to build, depends on nothing — placed late purely so it doesn't need rework as bigger systems land underneath it.

## Long-term (sequenced against each other only, not the list above)
10. **Difficulty system** — a global stat multiplier applied at enemy creation, with narrow hardcoded overrides for specific bosses where a formula doesn't feel right (e.g. Charybdis)
11. **New Game+** — depends on the game having an ending (#3) and on the difficulty system (#10) to scale a replay
12. **Unreal Engine port (C++)** — see `PORTING_NOTES.md` for accumulated visual/UX ideas gathered along the way; deliberately last, once the Python version is fully finished. **Decided over Godot**: the original appeal of Godot was GDScript's Python-like syntax, but with C++ as the actual goal, Unreal's native, mature C++ workflow is a better fit than fighting Godot's less-common C++ path (GDExtension).

## Kept separate — not yet decided whether/when to build
- **Numbered command shortcuts** (`1` instead of `north`; bigger win for multi-word commands like `take mentor's token from mentor` than for movement)
- **Weak points / unarmoured critical hits** — would sit on top of the helmet/body armour split (now built, see Completed), since "unarmoured" only means something once armour has more than one slot
- **Lower-level enemy respawning after time** — genuinely undersized to place yet.
