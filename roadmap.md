# Dungeon Crawler — Development Roadmap

Ordered by dependency, not necessarily by desire — each item is placed after
whatever it structurally relies on. Update this file as items are completed,
reordered, or new ideas come up.

(2) `dev spawn` was printing the raw `(message, None)` tuple instead of the message alone.)* *(Later migrated: the `DEV_MODE` module global (`dev_tools.py`) moved onto `Player.dev_mode` — a per-save instance attribute now round-tripped through `save_system.py` like any other `Player` field, rather than process-wide state that wouldn't persist across a save/load. See `CLAUDE.md`'s "Dev tooling" section.)*

- [x] Intellect stat — lives on `Player` only, set by ancestry, grown by 1 automatically on every `level_up()`. `Room` gained `examine_text`/`required_intellect`. ***Revised since*** — the original rule ("Intellect never gates required progress") was tightened: Intellect *can* gate progress, including the hidden-exit reveal itself, since it grows every level with no cap and nothing is ever permanently unreachable. *(Since then, intellect items raise it too, and three optional rooms are intellect-gated - see the "Hidden rooms" entry below.)*
- [x] Docstrings and comments retrofit — every function/class/method now has a docstring.
- [x] Enemy `choose_action()` + multiple enemies per room — built as team-vs-team from the start: combat resolution works over `player_team`/`enemy_team` plain lists (no `Team` class), player acting first each round followed by every still-living enemy via the standalone `choose_enemy_action()`. Utility-based scoring (`_score_candidate_actions()` plus random noise) across three actions: Attack, Defend/Brace, Heal. New player-facing `target <name>`/`target <name> <number>` command, with stable disambiguation numbering; `format_hp_line` generalized to a full N-combatant display. **Known follow-up, fix decided and now built** (see `CLAUDE.md`): Defend's score redefined around genuine incoming danger rather than raw missing-HP%.
- [x] **Companions** — `Companion(Character)` (real combat stats, unlike the stat-less `Ally`), holding `home_room`, `required_items`, and the same `aggression_weight`/`caution_weight`/`randomness_weight`/`brace_amount`/`heal_amount` fields as `Enemy`. `Player.companion` is a plain attribute; a new `Player.team` property returns `[player]` or `[player, companion]` (automatically excluding a downed companion, `hp == 0`). `recruit_companion()`/`dismiss_companion()` (`exploration.py`) mirror `trade_with_ally()`'s exact item-consumption mechanics, routed via `recruit <name>`/`dismiss`. `choose_companion_action()`/`choose_companion_target()` (`combat.py`) mirror `choose_enemy_action()`/`choose_enemy_target()` — separate functions per `CLAUDE.md`'s decision, though the underlying per-candidate scoring is fully shared. A downed companion isn't dead — `on_death()` returns a distinct "downed, recoverable" message; `Reviver(Consumable)` restores them (always ending the turn, and refused without being consumed when there's no downed companion - see the balance pass below), and dismissing a downed companion also restores them to full HP as a free alternative to a Reviver. `engine.py`'s `attack` handler now passes `player.team`, not a hardcoded `[player]`, so enemies can genuinely target a companion. *(Known-gap update: `dev spawn` now has a companion lookup (`COMPANION_REGISTRY`, backed by `content/dev_content.py`'s dev-only `create_test_companion()`), so `recruit` is reachable through `main()` via `dev spawn test companion` — see `dev_guide.md`. The first real one, the Shade of Achilles, is now placed on floor 5 - see the "Companion duels" entry below.)*
- [x] **Dodge ability** — new Abilities-path skill (`DodgeSkill`), a flat, additive `Character.dodge_chance: float` (default `0.0`, same precedent as `has_thorns`/`brace_amount`) checked at the very top of `take_damage()` — a successful roll (`random.random() < self.dodge_chance`) short-circuits the entire method, returning `0, "<name> dodges the attack!"` before any Defend/Brace or armour math runs, so a dodge means the hit never landed at all rather than being reduced to zero. Fourth skill in the Abilities path, alongside Double Strike/Thorns/Last Stand — deliberately breaks symmetry with Attack/Defence (five tiers each since the balance pass below), accepted as fine. Shipped as "Nimble Grace," currently a 35% chance (`chance=0.35`).
- [x] **Armour split — helmet and body** — `Armour` gained a `slot: str = "body"` field (`"body"` or `"helmet"`); `Character` gained two independent equip slots, `equipped_helmet` and `equipped_body`, replacing the old single `equipped_armour`. `Armour.use()`/`unequip()` read/write `getattr(character, f"equipped_{self.slot}")` — only same-slot items are ever swapped, so a helmet and a body piece can be worn simultaneously, each adding its own `defence` into the same `Character.armour` accumulator (mirrors how `Weapon` already works for `attack_damage`). *(Resolved as anticipated when this was planned: `Enemy` never needed to change — it still only has a flat `armour`/DEF number, no equip slots of its own. At the time, no content used `slot="helmet"`; the Weathered Helm, dropped by the Shade in Fields of Asphodel, is the first real one now.)* *(Since extended: a third `"shield"` slot, and `Character.armour` is now calculated from worn gear rather than accumulated - see the weapon-classes entry below.)*
- [x] **Armour durability + repair at the Forge of Prometheus** — `Armour` gained `max_durability: int = 10` / `durability` (starts full). `Character.take_damage()` decrements durability by 1 on every equipped piece (helmet *and* body) on every hit taken — even one fully blocked by armour — and once a piece's durability reaches exactly 0, its `defence` bonus stops counting (originally backed out of a running `Character.armour` total; now simply left out of the calculated one - see the weapon-classes entry below), though the piece stays equipped rather than auto-unequipping. **Subtlety worth remembering**: durability degrades *after* that hit's damage is already calculated, so the hit that actually breaks a piece still benefits from its defence — only the *next* hit loses the protection. `Room` gained `is_forge: bool = False` (only Forge of Prometheus, floor 2, is one). `repair_item(item_name, player, room)` (`exploration.py`), routed via `repair <item>`, only works at a forge, costs `REPAIR_COST_PER_POINT = 2` gold per point of missing durability, and restores full durability, re-adding the `defence` bonus if the piece had dropped to 0. *(Extended after playtesting found floor 3+ had no repair access at all: `max_durability` is now tuned per item instead of a flat `10` (cheap early gear breaks sooner, late-game gear lasts longer), a new `PASSIVE_REGEN_PER_MOVE = 1` restores a little HP on every move to soften pure attrition (later capped at three-quarters of max HP - see the balance pass below), and three new one-way `"forge"` shortcut exits (Prayer Room, Stony Lair, Maze of Pillars) connect straight back to the Forge without the long ascend chain. The Forge also gained three reciprocal exits back out to those same rooms (`Room.fast_travel_locks`/`exit_activations`, `world.py`), each locked until the one-way side has been used once. **A real bug found and fixed along the way**: the locking data model and world-wiring were built and round-tripped through saves correctly, but nothing in `main()`'s movement handling actually enforced it at first, so the reciprocal exits were unconditionally open from the start regardless of whether the paired room had ever been visited. Fixed by checking `fast_travel_locks` ahead of the existing item-lock check, and discarding the matching `exit_activations` entry on a successful move - see `CLAUDE.md`'s "Fast-travel locks".)*
- [x] **Status-effect items (poison/flame/heal-over-time)** — new `status_effects.py`: `StatusEffect(name, amount, duration)` — `amount < 0` deals damage each tick, `amount >= 0` heals; `tick(character)` applies one tick and decrements `duration`. `Character` gained `active_effects: list[StatusEffect]`, `apply_status_effect()` (reapplying an effect with the same name **prolongs its duration**, per the decided stacking rule — reapplication never changes `amount`, only `duration`), and `tick_status_effects()` (ticks every active effect, removing any that expire, and stopping the moment a tick kills the character — same "stop once dead" precedent as the combat round loop — appending the death message when that happens). `StatusEffectItem(Consumable)` (`items.py`) applies to the user themselves when `amount >= 0`, or to `player.current_target` when `amount < 0` (reusing the existing `target` command as the way to aim an offensive one, rather than a new `use <item> on <target>` syntax, as decided). Wired into `resolve_combat_round()`/`handle_combat_command()` so every combatant — player, companion, each enemy — ticks its own effects at the start of its own turn, with a lethal tick correctly skipping that combatant's turn entirely (a real bug found and fixed, same category as the player-death guard).
- [x] **Spells (offensive/defensive)** — new `spells.py`: `Spell(name, description, mana_cost, damage=0, heal_amount=0, effect_name=None, effect_amount=0, effect_duration=0)` — damage, heal, and status-effect components are all optional and freely combinable within one spell. `Player` gained `known_spells: list[Spell]`, `mana`/`max_mana` (both default `20`), `spell_cooldowns: dict[str, int]`, `tick_spell_cooldowns()`. `SpellBook(Consumable)` (`items.py`) permanently teaches its spell (raises if already known). New `cast <spell>` command (`handle_combat_command()`) validates known/not-on-cooldown/enough-mana, deducts `mana_cost`, and sets a flat 1-turn cooldown (every spell currently shares the same cooldown length — no per-spell variation yet). **Resource model, as decided and built**: mana recovers via a new `rest`/`wait` command (`engine.py`, exploration-only, `REST_MANA_AMOUNT = 10` per use) rather than passive per-turn regen. **`would_fail()` guard pattern, built to preserve "a failed action costs nothing"**: `Spell.would_fail(caster, target)` and `Item.would_fail(character)` (default no-op, overridden by `StatusEffectItem`/`SpellBook`, and later `Consumable`/`Reviver` too) let `combat.py` fully validate a `cast`/`use` *before* ticking anything. *(A real bug found and fixed here: ticking used to run **after** the action, so a freshly-cast spell's own new cooldown/effect could be immediately consumed by that same tick before it ever really took hold — cooldowns silently never blocked a repeat cast, and a self-cast heal-over-time got its first tick "for free" the instant it landed. Fixed by validating fully, then ticking pre-existing state, then committing the new action — so only state that existed *before* this turn is ever touched by "this turn's" tick.)* Spells are player-only for now — `Enemy`/`Companion` AI has no casting candidate action; that stays a possible future extension of the existing utility-scoring system, not built yet.
- [x] **Attack variety (light/heavy/ranged) + refined turn economy** — `Character.attack(target, attack_type="light")` now branches on `attack_type`: `"light"`/`"ranged"` deal a guaranteed hit (weapon-inclusive, no multiplier - since then, armour weight can make them miss too, see the weapon-classes entry below), `"heavy"` multiplies the total by `HEAVY_ATTACK_MULTIPLIER` (`1.75`) but has a `HEAVY_ATTACK_MISS_CHANCE` (`0.3` at the time, `0.4` since the balance pass below) chance to miss entirely (0 damage, turn still spent) — **decided heavy attack trade-off: a chance to miss, not a separate stamina resource**, as originally planned. `Weapon` gained a `slot: str = "melee"` field (`"melee"` or `"ranged"`), mirroring `Armour`'s helmet/body split — `Character` gained `equipped_melee_weapon`/`equipped_ranged_weapon` (replacing the old single `equipped_weapon`), and weapon damage is now read directly off the equipped slot at attack time rather than accumulated into `attack_damage` permanently. `handle_combat_command()`'s `attack` branch now accepts `attack`/`attack light`/`attack heavy`/`attack ranged` (an unrecognised type, or `ranged` with no ranged weapon equipped, returns an error message rather than attacking). **Refined turn economy**: `Item.ends_turn(character)` (default `True`, overridden by `Consumable`/`StatusEffectItem`) — a genuine heal is now a free action that doesn't end the turn (or let the enemy/companion act), while an offensive use, a non-healing use, or a spell cast still does. *(A real bug found and fixed while building this: `Character.turn_started` was never actually being set to `True` anywhere, so `tick_start_of_turn_if_needed()`'s guard against double-ticking status effects/cooldowns when a free action precedes a turn-ending one in the same round was a no-op. Fixed by setting it inside `tick_start_of_turn_if_needed()` itself.)* Spell attack variety (the `"spell"` option originally scoped here) was already covered by the existing `cast <spell>` command, so nothing further was needed there. Enemies/companions still don't use heavy/ranged themselves — attack-type variety is player-only for now, see `CLAUDE.md`.
- [x] **Practice chamber, with an infinitely-respawning, customisable practice dummy** — real, in-game content: a new "Practice Chamber" room on floor 2, connected east/west to the Forge of Prometheus, added to `build_floor_2()` (floor 2 now has six rooms, not five). `Enemy` gained `respawns: bool = False`; the room's dummy (`create_practice_dummy()`, `content/floor_2.py`) is the first (and so far only) enemy with it set. `Room` gained `is_practice_chamber: bool = False`. **Respawn mechanics**: `handle_enemy_defeat()` special-cases `enemy.respawns` — instead of removing the enemy and granting loot/XP/gold, it resets `hp` to `max_hp`, clears `active_effects` and `pending_damage_reduction`, and returns a "resets, ready for another round" message. `resolve_attack_and_check_defeat()` gained a `still_relevant_enemies` filter (excludes any `respawns` enemy; now `resolve_pending_defeats()`'s survivor check) so a solo respawning dummy correctly ends combat once "defeated," rather than looping forever since `handle_enemy_defeat()` just made it alive again. **Free spellcasting inside the chamber**: `handle_combat_command()`'s `cast` branch skips the cooldown/mana checks *and* skips deducting mana/setting a cooldown whenever `room.is_practice_chamber` — casting is entirely free while inside, exactly as originally planned (item and weapon use were already free of any resource cost, so nothing needed to change there). **Customisable stats**: reuses the *plumbing*, not the command, of `dev set <stat> <value>` as originally scoped — `dev_tools.py`'s core reflection/`STAT_ALIASES` logic was pulled out into a shared `_apply_stat()` helper, and a new `handle_dummy_set(stat_name, value_str, dummy)` reuses it for a genuinely new, undocumented-as-dev player command, `dummy set <stat> <value>` (message prefix `[Practice]`, not `[DEV]`; no `skillpoints` special case, since `Enemy` has no `skill_tree`) — routed in `main()` by finding the current room's `respawns` enemy, not gated by `DEV_MODE` at all. Added to `get_controls_text()`/the README's Controls section like any other real command.
- [x] **Ancestry system, expanded — primary + secondary ancestor** — a new `choose_secondary_ancestry(primary_key)` (`character_creation.py`) prompts for a second figure, excluding `primary_key` from the printed options and rejecting it if typed anyway (reprompting with a dedicated message) - **same figure can't be picked as both**, exactly as planned. `create_player()` gained a required third parameter, `secondary_ancestry_key`; it applies that entry's `secondary_effect(player)` callable and sets `player.secondary_ancestry_label` to the ability's description (shown as a new "Secondary gift: ..." line in `get_stats()`) - unless the secondary key matches the primary, or is `"basic"` (the deliberate "skip entirely" option, since `"basic"["secondary_effect"]` is `None`). Every `ANCESTRIES` entry gained `secondary_effect`/`secondary_ability_label`. **No stat effect from the secondary pick, ability only, exactly as decided** - each of the ten non-`"basic"` entries grants one flag on `Character`, checked far from the skill tree's own four ability flags: `has_reckless_strength` (Ares - removed the heavy attack miss chance entirely, `attack()`; now halves it instead, see the balance pass below), `has_measured_casting` (Athena - spells never go on cooldown, `handle_combat_command()`'s `cast` branch - mana is still required/deducted normally), `has_swift_feet` (Hermes - `flee_combat()` always disengages cleanly, no free-hit roll at all), `has_unyielding_tide` (Poseidon - `take_damage()` never backs out armour's `defence` when a piece's durability breaks, though durability still degrades), `has_berserking` (Achilles - `attack()` adds +2 damage at or below half HP), `has_silver_tongue` (Odysseus - `trade_with_ally()` never actually removes the required items, though the trade still completes and the reward is still granted), `can_ranged_without_weapon` (Atalanta - `handle_combat_command()`'s `attack ranged` works with no equipped ranged weapon), `has_petrifying_gaze` (Medusa - `attack()` has a 15% chance to also poison a target that survives the hit, skipped entirely if the hit kills it), `has_bull_rush` (Minotaur - `attack()` adds +3 damage against a target still at full HP; now added after the heavy multiplier rather than before it, see the balance pass below), `has_iron_hide` (Cyclops - `take_damage()` reduces the final damage by 1, floored at 0 - now at `MINIMUM_DAMAGE` instead, see the balance pass below). *(Four real bugs found and fixed while building this: (1) the `cast` branch's mana check got nested inside a condition that made it unreachable for every player, not just those with `has_measured_casting` - fixed by restoring independence between the cooldown check (guarded by the flag) and the mana check (always enforced outside the practice chamber). (2) `has_reckless_strength` was declared and grantable but never actually read anywhere - `attack()`'s heavy-miss roll was unconditional until the flag was added to its condition. (3) A typo (`has_silver_tonuge`) in Odysseus' `secondary_effect` meant Silver Tongue could never trigger - the correctly-spelled attribute it should have set was never touched. (4) `create_player()` stored the ancestry's *primary* label into `secondary_ancestry_label` instead of the ability description, so the stats screen's "Secondary gift" line just repeated the ancestry name instead of saying what the gift actually did.)* `dev set <flag_name> 1` (the existing generic `dev set` command, unmodified) happens to work for granting any of the ten flags directly for playtesting, since `setattr` doesn't care that the value arrives as an `int` rather than a `bool` - see `dev_guide.md`.
- [x] **Save/load system — 3 profiles, 5 slots each, with a full title screen (New Game / Load Game / Delete Save / Quit).** New `save_system.py` owns serialisation/deserialisation and file I/O only: `slot_path`/`ensure_profile_dir`/`slot_exists`/`slot_summary` for profile/slot bookkeeping (`saves/profile_N/slot_N.json`), `serialise_player`/`player_from_save_data` for a full `Player` snapshot (stats, all 13 `ABILITY_FLAG_NAMES` flags, `dodge_chance`, skill tree unlock counts + points, gold/level/XP/mana, both ancestry labels, `visited_floors`, known spells + cooldowns, active effects, inventory with equipped/durability, companion + its own active effects), `serialise_room`/`apply_room_data`/`serialise_world`/`apply_world_data` for room state, and `save_game`/`load_game`/`delete_save`/`delete_profile` tying it together. New prompt functions in `character_creation.py` (`choose_title_screen_action`, `choose_profile`, `choose_slot`, `choose_occupied_slot`, `confirm`) drive the title screen and every save/load prompt, exactly as planned. `main()` tracks a single "active slot" (`active_profile`/`active_slot`), set by New Game, Load Game, or any confirmed `save <profile> <slot>`/`load <profile> <slot>` - bare `save` and autosave both always target it. **Manual save/load work as decided**: bare `save` (no confirmation), `save <profile> <slot>` (confirms only if occupied), `load <profile> <slot>` (always confirms, even reloading the active slot; an empty target errors without prompting). **Autosave** fires the first time `Player.visited_floors: set[str]` (keyed by `build_world()`'s floor names like `"floor_0"`, checked via `find_floor_for_room()`) gains a new floor - re-crossing an already-visited boundary never re-triggers it. **Deviates from the original plan in two deliberate ways**: every room gets a full snapshot on every save, not a delta of only changed rooms (`save_system.py`'s own module docstring: real change-tracking would need a proper `Room.touched` flag, and JSON size for a text-game map is trivial enough that this is a safe simplification, not an urgent shortcut); and locked-exit state (`unlocked_extras`/`locked_exits_removed` in `serialise_room()`) was left as an unfinished placeholder - since superseded by a real `"locked_exits"` list, once doors started staying open (see the weapon-classes entry below). **Enemy matching on reload, later fixed**: enemies were first matched by name alone, not name + ordinal position as originally planned, and anything spawned mid-fight was dropped - see the "Save/load: enemies spawned mid-fight, and a fresh world on every load" entry below. **Whole-profile deletion** (`delete_profile()`) exists in `save_system.py` but isn't wired into the title screen yet - only per-slot `delete_save()` is reachable through `main()`. *(A real bug found and fixed: the title screen's Load Game action originally called `choose_slot()` (lists every slot, empty or not) instead of `choose_occupied_slot()` - picking an empty slot reached `save_system.load_game()` on a nonexistent file and crashed the whole game with an uncaught `FileNotFoundError`. Fixed by switching to `choose_occupied_slot()`, whose genuine `None` return now actually reaches the existing `if slot_num is None: continue` guard.)* **Later extended: death no longer always ends `main()`.** The per-life game loop now sits inside an outer `while True:`, and dying prompts `"You have died. Reload your last save?"` - declining ends the game as before, accepting reloads the active slot fresh and continues playing. *(A second real bug found and fixed here: the inner loop's exit condition couldn't tell a `quit`/`exit` break apart from an actual death, so quitting normally falsely triggered that same reload prompt. Fixed with a `quit_requested` flag checked immediately after the inner loop, returning before the death-reload logic runs.)* See `CLAUDE.md`'s "Save/load system and the title screen" for the full breakdown.
- [x] **Multi-stage boss fights — decided design confirmed: no dedicated `Boss` class.** A boss is still a plain `Enemy` — `next_phase_factory` (a callable, following the existing `create_*()` factory pattern) triggers a seamless phase transition in `handle_enemy_defeat()`, not inside `on_death()` itself: combat stays locked, `current_target` automatically updates to the next phase. **Extended beyond the original scope with a wave-gate mechanic**: `next_wave_factories` (a list of factories) spawns a set of ordinary adds instead of transitioning immediately - each add gets `wave_gate_factory` set to the phase's own deferred `next_phase_factory`, carried on the adds themselves rather than tracked on `Room`/`Player`. Whenever a `wave_gate_factory`-tagged enemy dies, `handle_enemy_defeat()` checks `room.enemies` fresh for any remaining sibling sharing that same factory (matched by identity, not equality; a dead-but-unprocessed sibling still counts, so a whole wave dying in one round spawns the next phase exactly once) - only once none remain does the next phase actually spawn, correct regardless of kill order. New dev-only `create_test_boss()` (`content/dev_content.py`) exercises the whole chain end-to-end - a two-phase boss whose first phase is gated behind a two-add wave - registered in `ENEMY_REGISTRY` as `"test boss"`, reachable via `dev spawn test boss`. *(A real bug found and fixed alongside this: `resolve_attack_and_check_defeat()` cleared `player.current_target` to `None` on every defeat and only ever re-set it for a phase-transition - defeating one enemy in a multi-enemy fight with no transition left `current_target` unset until the player's next `attack`/`target` command. Fixed by auto-selecting the next living, still-relevant enemy when `current_target` is still `None` after the defeat loop.)* **A real, named boss now exists**: Medusa (floor 4, Lair of Medusa - Phase 1 falls to a wave of two Gorgons, then Medusa (Awakened) appears). Hades and Typhon are still unplaced - see "Populate all floors" below. *(Her stats went through a real balance pass after playtesting found the original tuning made the fight a near-binary pass/fail depending on which skill path the player had invested in, rather than genuinely hard-but-winnable - see `CLAUDE.md`'s "Multi-stage boss fights" for the current numbers and what was actually wrong.)* See `CLAUDE.md`'s "Multi-stage boss fights" for the full breakdown.
- [x] **Balance pass — minimum damage, guarded exits, capped regen, five-tier stat skills, and an ancestry rebalance.** Driven by a `/balance-check` audit plus a disposable, fight-by-fight simulation of floors 0-4 (real content, real combat functions, carrying HP/durability/potions/XP across fights). The audit found the baseline was bimodal rather than "medium": build and ancestry choice decided the outcome far more than play did. **What changed**:
  - **`MINIMUM_DAMAGE = 1`** in `take_damage()` - no landed hit is ever fully absorbed any more. This removed the flat-armour cliff that made pure-Defence builds invulnerable.
  - **`Room.guarded_exits`/`guard_exit()`** plus `get_exit_guardian()` (`exploration.py`), enforced in `main()`'s movement branch. Overgrown Forest's `descend`, the Labyrinth's `south`, Maze of Pillars' `south` and Lair of Medusa's `descend` can't be used past a living guardian. Previously every fight could be walked past, including the Minotaur, which is meant to be a hard skill gate.
  - **Passive regen capped** (`PASSIVE_REGEN_CAP_FRACTION`). Uncapped, pacing between two cleared rooms healed to full for free. It went in at `0.5`, but a follow-up audit found that, combined with `MINIMUM_DAMAGE`, a careful floor 4 run reached almost every fight at 7-12 HP and usually died at Medusa, so it was raised to `0.75`.
  - **`take` became a free combat action.** The Gorgons' potion drops were landing on the floor mid-fight where `take` couldn't reach them, so the Medusa chain's intended sustain never existed.
  - **Attack/Defence paths now have five tiers each at `2/3/4/5/6`**, previously three at `2/4/6`.
  - **`HEAVY_ATTACK_MISS_CHANCE` raised to `0.4`.** At `0.3`, a heavy attack out-damaged a light one on average for every build.

  - **Random chests** roll from a **`LootTable`** (a gold range, weighted item factories, a number of rolls) - `EARLY_LOOT`, `MIDDLE_LOOT` and `LATE_LOOT` in the new `content/loot_tables.py`. Plain items only: everything in a table is something Charon sells (or the Bronze Xiphos), never earlier than he'd sell it, with gear rarer than healing (reversed since - see the "Second late-game balance pass" entry below).
  - **Rolls can't be rerolled by reloading, as decided**: **`Player.run_seed`** is set once per new game and saved; each chest uses its own `random.Random` seeded from `zlib.crc32` of the seed and the room's name - not Python's `hash()`, which changes every run - so chest rolls and the game's other random numbers never touch.
  - **Six chests placed**, each behind a fight: Sunken Vault and the Throne Room of Odysseus (fixed), Cave of Harpies, Stony Lair, Shadow of Troy (Central) and Bright Cave (random). The five factories the loot tables share with Charon's stock moved to `content/common.py`.
  - **Deviations from the plan**: the loot tables are per stage of the game (three), not per floor; and items are rolled with replacement, so a chest can hold two of the same thing.
  - **Still to do, deliberately**: chest gold and loot haven't been through `/balance-check`'s gold measurement yet - they belong in the same balance as Charon's prices.

  *(A real bug caught before shipping: `exploration.py` and `chests.py` imported from each other, so the game wouldn't start and not one test file could be collected. Fixed by keeping the dependency one-way - `CHEST_OPENED` lives in `exploration.py`. See `CLAUDE.md`'s "Searchable chests".)*

- [x] **Gear upgrades at Daedalus' Workshop.** The hidden Workshop on floor 4 now has a lasting purpose, and gold a real sink: new `upgrades.py`, and an `upgrade` command that only works where `Room.is_workshop` is set.
  - **The design points, as settled**:
    - **What an upgrade improves** - +1 damage (weapons) or +1 defence (armour) a level. Not durability, and never a signature property.
    - **How many times** - five (`MAX_UPGRADE_LEVEL`), but limited by intellect: `upgrade_cap()` is `1 + intellect // 3`, so +1 for anyone and +5 at 12 intellect. The cap only stops further upgrades - nothing is ever taken away.
    - **The cost** - the item's value before upgrades (at least 40), times the level being bought (`upgrade_cost()`): 70, 140, 210, 280, 350 for the Labrys.
  - **Built so an upgrade can't be applied twice**: `Item.upgrade_level` is the only thing stored. `Weapon.damage` and `Armour.defence` became properties that add it to `base_damage`/`base_defence`, so combat, `Character.armour`, the inventory's stat lines and item values all pick upgrades up with no code of their own - the lesson of the armour double-counting bug.
  - **Saving** - `upgrade_level` is saved with every item, in the inventory and on a room's floor, and reapplied when items are rebuilt by name; an older save loads plain items. An item's `name` never changes - **`Item.display_name`** ("Labrys +2") is what every player-facing message shows.
  - **Interactions, as planned** - selling accounts for upgrades (`item_value()` reads the upgraded stat; each level adds far less to the sale price than it cost), and unique items are upgradeable.
  - Bare `upgrade` lists every weapon and armour piece with its next level's cost, or why it can't go further. An eleventh one-off hint, `"workshop"`, explains it on entering. `upgrade` was added to `get_controls_text()` and the README.
  - **Deviation from the plan**: the intellect limit wasn't in it - it makes intellect matter beyond finding hidden rooms. **Still to do**: the costs haven't been through `/balance-check`'s gold measurement.

  *(Real bugs caught before shipping, each regression-tested: (1) **`inventory` crashed the game as soon as the player held an upgraded weapon** - the display counted items by display name and looked them up by plain name; on the way there it showed every item as "x2", and hid an upgraded copy beside a plain one. (2) **An upgraded item dropped on the floor reloaded at +0** - rooms saved items by name and durability only. See `CLAUDE.md`'s "Gear upgrades at Daedalus' Workshop".)*

- [x] **The Trophy Room of Zeus - a physical room, thirteen trophies, and Zeus himself.** Built as decided: a room, not an ally-respect mechanic. New `trophies.py` and a `place` command that only works where `Room.is_trophy_room` is set.
  - **Thirteen plinths, one per trophy in the game** (`TROPHY_PLINTHS`), each with a clue shown while it's empty - the room's description lists them all, and never names a trophy that isn't placed. `place <trophy>` sets one; `place all` sets every one carried. Placed trophies leave the inventory and are saved with the room (`Room.placed_trophies`).
  - **Milestone rewards**, each paid once and recorded in the room's flags: at 5, +5 max HP; at 10, a skill point; at all 13, the room is complete (`"trophy_room_complete"`).
  - **The chest**, as planned - "placing every trophy unlocks a chest" - built on the chest system with a new `can_open` condition in place of the cleared-room rule. It holds the **Thunderbolt of Zeus**, the best ranged weapon in the game (12 damage, pierce 4, 25% blind), made ranged so it sits beside an upgraded favourite rather than replacing it.
  - **Zeus** is in the room from the start, as a `Companion` who explains the plinths and won't join until they're full - then he's the strongest companion in the game. He has a line for his brother Hades (`Companion.companion_lines`, the companion's version of `Ally.companion_lines`).
  - **Deviations from the plan**: (1) trophies aren't only boss drops - eight are (the Minotaur, Talos, Medusa, Polyphemus, Poseidon, Cerberus, Hades and Typhon), and five lie in hidden rooms (the Lethe, the Ossuary, Daedalus' Workshop, the Wooden Horse, the Cave of the Nymphs), so the hidden rooms matter to completing it; (2) the milestones, `place all` and Zeus as a companion weren't in it. `Trophy` stayed a `QuestItem`, as already noted.
  - Outside the room, `place` answers "There's nowhere here worthy of it." without naming it - the room is hidden. `place` was added to `get_controls_text()` and the README.
  - `test_content.py` guards the whole set: every plinth names a real trophy, every trophy can be found exactly once (in any phase or wave of a fight, or on a room's floor), and every trophy has a plinth.

- [x] **Second late-game balance pass - tougher bosses and side rooms, one Suitor fewer, and one-item chests.** Chests, Charon's shop and gear upgrades had each made a careful player stronger, and a `/balance-check` on the finished game found the result: **no deaths in 1800 careful runs**, Typhon leaving them 15 of 37 HP, about 30 unused healing items at the end, floor 4's side rooms over in two turns, and the Throne Room - five attackers - still the one fight that singled out defence-first players (14% of careless ones died there). Retuned by hand, then measured again:
  - **Floor 4's side rooms**: Petrified Guardian `21` HP / `7` attack, Satyr `31` / `7`, Lamia `36` / `8`, Ember Wraith `34` / `8` (about a fifth more HP and +1 attack each). They last 3-4 turns for a balanced build now.
  - **Floor 5**: Hector `39` / `11`, Ajax `56` / `13`, the Myrmidons `27` / `10` with pierce `3`, Paris `24` HP with pierce `9`. On target for defence-first players (the Myrmidons take them to 13 of 23); **still gentle for the other two builds**, who lose 1-4 HP a fight - attack-first by ending fights in 1-3 turns, balanced by wearing 15-18 armour. More HP, not more attack, is the lever left.
  - **The Throne Room has two nameless Suitors, not three** - four attackers. Careful players bottom out at 11-18 of 26 HP, and under 1% of careless ones die there. The room pays 115 gold instead of 130. Odysseus' warning counts four.
  - **Cerberus `90`/`82`/`72`, Hades `100`/`100`, Typhon `110` and `135`** - about a fifth more HP, nothing else. Hades takes careful players to 10-18 of 35 HP, Typhon to 4-8 of 37 (8-14 with upgrades bought).
  - **Random chests hold one item, not two, and lean towards gear**: every table passes `rolls=1`, with a little more gold (15-30, 25-50, 35-65). Early: potion 2, dressing 2, xiphos 3. Middle: poultice 3, buckler 3, greataxe 3. Late: kykeon 2, obol 2, hoplite sword 3. The old "gear is rarer than healing" rule is gone on purpose - gear sells, healing piled up. Careful players still end with about 23 healing items unused, down from 30: enemy drops and ally gifts are the main source, not chests.
  - **Where it landed**: careful players die in about 1 run in 900, careless full-clearers in 1-4% (Rocky Shore is the main killer), and a player who skips the side content is still stopped at the Minotaur. Gold is unchanged in shape - about 1200-1550 unspent without upgrades, about 150-180 with them. That reads as the "medium" the difficulty system scales from (built since - Normal, see the next entry).

- [x] **Difficulty system - four settings, one scaling function, and hardcore tied to Hard.** Built as decided: Story, Easy, Normal and Hard, chosen at a new game (`choose_difficulty()`), fixed for the run, saved with the player (`Player.difficulty`) and shown at the end of every slot's summary line. New `difficulty.py`, which imports nothing else from the game.
  - **What a setting changes**: enemy HP and attack, and passive regeneration - nothing else, so healing found, gold and XP need no retuning, and an easier setting helps whether or not the player explores (the "upgrades widen the gap" point). Story x0.5 / x0.5, 2 HP a move to full; Easy x0.75 / x0.8, 1 to full; Normal unchanged (the baseline of the v2.1.0 balance passes); Hard x1.3 / x1.2, 1 up to half. Charybdis' puzzle damage scales with attack. The regen constants left `engine.py` for the `Difficulty` dataclass, and the regen hint split in two, since "only part of the way" is untrue on Story and Easy.
  - **One scaling function, called by every route an enemy is created**: `scale_enemy()` always works from **`Enemy.unscaled_max_hp`/`unscaled_attack`**, so scaling twice or to a new setting never compounds; current HP keeps its share (or, on loading, its exact saved value); respawning enemies are never scaled. Routes: a new game and loading (`scale_world()`), a wave's adds, a next phase and the phase after a wave (`handle_enemy_defeat()`), the duel form, and `dev spawn` - each with a test, and one that plays every multi-stage fight to its end on Hard. New Game+'s Thanatos (#7) will be one more.
  - **Changing the setting mid-run** needs no access to the world: `scale_world()` records what it scaled for (`Map.scaled_for`), and `main()` calls `ensure_world_scaled()` before every command, which rescales only on a mismatch. Prometheus and the new `dev difficulty <setting>` both just change the player.
  - **New Game+ is already in the maths** - `Player.ng_plus_cycle` (saved, always 0 for now) adds 25% per cycle to both multipliers, added rather than compounded.
  - **Hardcore**: accepting Prometheus' offer raises the run to Hard - the one exception to a fixed setting, only ever upwards - and the world rescales, each enemy keeping its share of its HP. `quit` saves first, and quitting mid-fight counts as an ordinary flee before that save; a hardcore run also saves on every move, so closing the window costs the current room at most; and mid-game `load` is refused. His "Be sure" step says all of it.
  - **Deliberate deviation**: the plan had loading a hardcore save use it up. That was built and dropped - the next move wrote the save again, so it didn't stop a player closing the window mid-fight and reloading, and a crash straight after loading cost the whole run. Refusing `load` closes the flee-then-load route instead. **Still open, by design**: closing the window mid-fight and loading from the title screen returns to the room's entrance.
  - **Not done yet**: the four sets of numbers are starting values - `/balance-check` has only measured Normal.

  *(Bugs caught before shipping, each regression-tested: the phase that follows a cleared wave was never scaled, so Medusa (Awakened), Poseidon (Earth-Shaker), Hades (Helm of Darkness) and Typhon (Storm Unleashed) appeared at Normal strength on every setting; `dev spawn` crashed for anything that wasn't an enemy; `scale_world()` was first handed a list of rooms rather than the world, so every new game crashed and every load was refused as a damaged save; dying to a parting blow on a hardcore `quit` left the save on disk; and the first fix for that made every ordinary `quit` count as a death.)*

## In order

1. **Drop chance on respawning enemies.** Today a `respawns` enemy grants nothing at all - `handle_enemy_defeat()`'s respawn branch resets it before the loot/XP/gold code is ever reached. Planned: a per-enemy chance (e.g. `Enemy.drop_chance: float = 0.0`) rolled with `random.random()` (so it stays monkeypatch-testable, same convention as the heavy-attack and dodge rolls) each time a respawning enemy is "defeated", dropping its loot into the room on a success. **Design point to settle first**: `Enemy.loot` holds item *instances*, so a repeatable drop can't just re-drop the same objects - it needs a fresh item per drop, most likely a list of `create_*()` factories (the same pattern `next_phase_factory`/`next_wave_factories` already use). **Open questions**: whether a successful roll also grants XP/gold or loot only, and whether the Practice Chamber's dummy should ever get a drop chance at all - it's meant to be a reward-free testing space (its one-off hint says as much), so this is really aimed at future respawning content, including the "lower-level enemy respawning after time" idea kept separate below. Originally placed before the floors were populated; they were finished without it, so it's now aimed at future respawning content rather than the existing floors.
2. **Trial mode - finite, scaling rounds inside the main game.** **Decided shape**: a set number of rounds, each harder than the last, played inside the normal game world rather than as a separate mode on the title screen - and genuinely *beatable*, with a clear completion, unlike the endlessly-respawning Practice Chamber dummy. **Eventually tied to an achievement** for clearing it, once achievements exist (#3) - the trial itself doesn't need to wait for that, only the reward hook does. Placed after floors are populated, since the round rosters should draw on the full set of real enemies. **Worth reusing rather than rebuilding**: the wave mechanic (`next_wave_factories`/`wave_gate_factory`) already chains "clear these, then the next thing appears", and a round's scaling could share the difficulty system's stat multiplier (`enemy_multipliers()`, built - see Completed) rather than inventing a second one. **Open questions**: where in the world it lives, what exactly scales between rounds (stats, enemy count, enemy mix), whether dying in a trial is a real death or just a failed attempt, whether it can be retried, and what clearing it rewards beyond the achievement.
3. **Achievements, tied to a profile** — genuinely depends on save/load (see Completed — Save/load system), specifically the profile layer. Placed after floors are finished, since that's when the full roster of things worth achieving actually exists. First known achievement to wire up: clearing trial mode (#2) - and clearing the game on hardcore (see the "Hardcore mode" entry in Completed).
4. **Carry weight / inventory cap** — gives real purpose to the existing `drop` command. Cheap to add: give `Item.__init__` a `weight: int = 1` default. **Quest items must be exempt from the cap.** Placed after the floors are finished. **Decided shape**: a fixed base capacity for everyone, only ever modified by a one-time ancestry bonus and/or a skill/ability, never by levelling. **Resolved: equipped gear still counts toward the cap.**
5. **Standalone `.exe` build via PyInstaller** — `pyinstaller --onefile` bundles the whole game into a single downloadable executable. **Decided: automate via the existing GitHub Actions workflow** — extend it to build the `.exe` and attach it to the GitHub Release automatically on a version tag push. Windows-only per platform it's run on; file size 10–30MB; antivirus false positives are a known, harmless PyInstaller quirk. Placed last among the "real" content/systems.
6. **Easter egg: UUDDLRLRBA input sequence** — grants a secret legendary item or activates God Mode. Genuinely trivial to build, depends on nothing — placed late purely so it doesn't need rework as bigger systems land underneath it.

## Long-term (sequenced against each other only, not the list above)
7. **New Game+ — decided shape.** Builds on the difficulty system (built - see Completed), which already scales by cycle: `Player.ng_plus_cycle`
   is saved and `enemy_multipliers()` adds 25% per cycle, so starting a cycle only has to raise the number. Started with a room verb in the Trophy Room
   once it's complete, so it works whether Zeus is there or in the party; two steps, since it's permanent, continuing in the same save slot.
   - **Carried over**: the character exactly as they are - level, skills and stats, so one-off boons stack each cycle - and every recruited
     companion, with their levels and state. Hardcore carries over. **Left behind**: gear and upgrades, gold, trophies, story flags and the
     world. Hints seen stay seen; a new run seed rerolls chests.
   - **Difficulty**: the same setting, plus a stacking multiplier per cycle (start at +25% enemy HP and attack). XP rewards aren't
     scaled. There's no hard level cap, only a soft one - the XP one run's placed enemies can pay - and a carried character arrives having
     reached it. Each cycle's enemies pay XP again, so every cycle raises that soft cap (as trial mode (#2) would).
   - **Carried companions** are removed from their starting rooms, then either in the party or waiting in their home room.
   - **A carried Hades**: his home becomes Persephone's bedchamber. **Thanatos** holds the Hall's throne instead - a new multi-stage boss at
     Hades' place on the difficulty ladder, wearing and dropping the Helm of Darkness, so the Trophy Room stays completable. Persephone's
     promise counts as kept (the descent opens; she reacts to Hades through `companion_lines`; the Pomegranate is still given). Hades gives
     the reveal himself when Thanatos falls; clearing the Hall still sets `'hades_defeated'`.
8. **Unreal Engine port (C++)** — see `PORTING_NOTES.md` for accumulated visual/UX ideas gathered along the way; deliberately last, once the Python version is fully finished. **Decided over Godot**: the original appeal of Godot was GDScript's Python-like syntax, but with C++ as the actual goal, Unreal's native, mature C++ workflow is a better fit than fighting Godot's less-common C++ path (GDExtension).
